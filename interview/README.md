# Interview prep

Two phases, in order. The order is the whole method.

1. **Learn.** Read or watch the pattern, then copy two worked examples by hand.
2. **Drill.** Solve 8 to 10 problems, easy then medium, no time limit.
3. **Narrate.** Solve 2 problems under time, out loud, no run button.

A topic is **learned** only when I explain it out loud for 60 seconds, without
notes, and it does not break. A problem is **done** only when solved once,
unaided, under time. Watching a video is neither.

The reason for the order: on new and complex material, a performance goal set
before the strategy is known makes people scramble and learn less. Locke and
Latham (2002) call the fix a *learning goal*: find the strategies first, then
put a number on the performance.

## Layout

| Path | Holds |
| --- | --- |
| `progress.md` | The 16 topics and their real state |
| `patterns/` | One note per pattern, in my own words |
| `mocks/` | One score sheet per recorded mock |
| `designs/` | One written system design per week |
| `results.tsv` | One row per counted action, readable by the weekly review |

## Rules

- Recordings stay local. Commit the score sheet, not the audio or the video.
- No solution copied into this folder until the problem is solved unaided once.
- The score sheet is filled after the mock, from the recording, not from memory.
